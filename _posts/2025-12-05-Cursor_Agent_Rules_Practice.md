## Agent 不是越放权越快

Cursor 适合在仓库里连续改：网关、监控脚本、部署清单。指令含糊时（例如「优化一下限流」），它会顺手重构半个目录。按任务分层：

- 补测试、加日志字段：直接交给它
- 局部 bug、加参数：可以，但点名文件
- 灰度路由重构这类：先自己定方案，再让它按步骤改

## Rules 比提示词耐用

没有约定时，它会发明配置项、乱升级依赖、扩 scope。仓库里写清楚：目录结构、Python 版本、日志必须带 `request_id`、禁止硬编码 Key、动鉴权/限流先出方案、改完列出验证命令。

规则不用长，几条反复踩过的坑就够。每次纠错都补进规则，比每次对话重新骂它有效。

## 喂上下文的方式

先 `@` 关键文件再提需求；一次只干一件事；明确「别动 Dockerfile、别升依赖」。长需求拆成：先复述现状 → 确认范围 → 再改 → 给 Diff 摘要和测试结果。

例：给网关加模型级 QPM。提示里写清背景（已有全局限流）、目标、约束（不改对外路径、用现有 Redis）、验证（`pytest` + curl 打出 429）。先让它讲现状，讲对了再授权改。

## 常见翻车

编造不存在的配置——要求引用真实路径。
顺手大重构——写死可改文件列表。
测试没跑就说完成——强制要验证命令和结果。

和 Claude Code 的分工也简单：Cursor 做本地深度改和看 Diff；终端任务、靠近运行环境的排查用 Claude Code，且权限隔离。两边都不是免审通行证。
