## 问题

渠道和令牌被当成同一个东西。结果要么调用方拿到上游真 Key，要么模型名对不上：渠道测试是通的，客户端却 404 或 401。

## 区别

- **渠道**：一个上游一条。里面是 Base URL、上游 Key、模型映射、分组。调用方看不到。
- **令牌**：发给调用方的 Key，只在 New API 里有效。额度、过期、模型白名单、IP 都写在令牌上。

一个上游一个渠道。模型名对齐引擎的 `--served-model-name`。分组先分开，例如 `default` 和 `internal`。保存后点测试。对外名字可以映射，不要和引擎内部名写在同一处还指望自动对齐。

## 发令牌

- 名称按应用：`dify-prod`、`zcode-dev`
- 绑定分组，不跨组乱用
- 正式环境限额度、写过期
- 模型限制只放开要用的，不要默认全开
- 有固定出口就写 IP

发给调用方只三行：Base URL、Key、可用模型。完整 Key 不进群，截图也不行。

## 对不上时先分清是哪一层

| 现象 | 先看 |
|------|------|
| 401 | 令牌复制少了、已禁用、已过期 |
| 模型不存在 / 无权限 | 令牌白名单，或渠道映射的对外名 |
| 渠道测试失败、令牌还没发 | 上游地址或上游 Key |
| 测试通、调用方不通 | Base URL 少了 `/v1`，或填成了引擎地址 |

停用账号时，先禁用对应令牌。不要只从通讯录里删人，令牌还在就能继续打。
