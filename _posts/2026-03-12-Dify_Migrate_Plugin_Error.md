## 现象

测试环境一切正常，整包镜像 + 数据迁到生产后，过几天点知识库报错，类似 `Invalid plugin id ...`（社区 issue 里也有 Xorbits Inference 一类插件 ID 无效的报告）。应用对话有时还能用，知识库控制台先炸。

## 原因归纳

迁移时容易只同步了 Postgres 数据卷和主应用镜像，忽略：

- 插件安装状态 / 插件包本身
- `SECRET_KEY` 等与加密存储相关的密钥不一致
- 向量库、对象存储只迁了一半

插件记录在库里，二进制或插件守护进程不在，界面一解析知识库相关插件就报 invalid。

## 处理步骤（实操向）

1. 对齐生产与测试的 `SECRET_KEY` 及文档列出的关键环境变量（以当前版本官方迁移说明为准）
2. 确认插件服务容器健康，必要时按官方命令重装/修复插件
3. 向量库与 MinIO/S3 数据与 DB 同期迁移，避免「库有文档、文件 404」
4. 迁移后先跑：登录 → 知识库列表 → 检索测试 → 一个最小工作流，再切流量

离线环境更要固定插件版本，别假设「镜像能起 = 插件生态完整」。

## 教训

Dify 迁移不是 `docker compose up` 成功就结束。知识库链路依赖插件、存储、密钥三条线，缺一条都会以很怪的前端错误出现。后来我们迁移清单里把「知识库点开 + 检索测试」写成必测项。
