多模态模型同时啃文本、图像，有的还能吃视频和音频。比单模态「全面」是真的，但训练贵、评测乱、失败模式也更多——图对了文错了、文对了时间轴错了，都常见。这篇按融合方式和产品选型记，不堆型号年表。

## 模态组合

- **图文：** CLIP / BLIP 做对齐与生成；GPT-4o、Claude、Gemini、Qwen-VL 做通用视觉对话  
- **视频：** Video-LLaMA、Video-ChatGPT，以及 Gemini 等闭源；本质多是抽帧 + 时序建模 + LLM  
- **音频：** SpeechT5、Whisper（偏语音）、以及把音频 token 化后塞进 LLM 的路线  

「原生多模态」和「后期拼接」体感差很多：前者从训练目标就按多模态设计；后者灵活、但对齐裂缝靠投影层硬补。

## 融合：早、中、晚

**早期融合**在输入侧拼特征，简单，弱模态易被淹没。  
**晚期融合**各模态独立推理再合并，好调试，难做细粒度交互。  
**中间融合 / 交叉注意力**最常见：文本 query 去看视觉 key-value，或对比学习先对齐再融合。

CLIP 证明对比学习能学到可迁移的共享空间；生成式 VLM 则在对齐后再做自回归/指令微调。做系统时我关心的是：分辨率多高、一次几张图、视频抽几帧、音频是否另走 ASR——这些「工程模态」往往比论文结构图更影响效果。

## 两个常用闭源锚点

**GPT-4o / 原 4V 路线：** 图文问答、草图、简单文档分析都强，工具生态熟。

```python
from openai import OpenAI
client = OpenAI()
print(client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "指出图中可能的安全隐患"},
        {"type": "image_url", "image_url": {"url": "https://example.com/shop.jpg"}},
    ]}],
).choices[0].message.content)
```

**Gemini：** 视频和长上下文是卖点，和 Google 生态集成紧。选型时拿同一批「带时间问题」的视频 case 对比，比看宣传页准。

开源侧用 Qwen-VL、LLaVA 派生系列做私有化，接受自己做安全与幻觉治理。

## 应用里真正值钱的点

智能客服收截图、教育题讲解、媒资检索（文搜视频）、内容审核、文档/表格理解。交互上「用户丢一张图 + 一句话」已经是默认形态；摄像头 + 语音的实时多模态也在部分场景落地，但对延迟和带宽更敏感。

注意局限：

- 细小文字、密集表格：先 OCR 再推理往往更稳  
- 视频时间定位：「第 3 分钟谁进门」容易含糊，需要片段级检索  
- 音频情感/叠音：单独模型有时比硬塞进通用 MLLM 好  

## 趋势（和我的偏见）

统一 tokenizer / 统一 transformer 吃所有模态，是大厂方向；更长上下文让「一堆图 + 说明书」成为可能；端侧小多模态会起来，但质量仍明显弱一档。对我来说，多模态项目的成功标准很土：**关键信息有没有从像素/波形进到最终决策**，而不是模型是否支持十种输入格式。
