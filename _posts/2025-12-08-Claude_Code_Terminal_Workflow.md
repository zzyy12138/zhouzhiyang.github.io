## 它出现在什么位置

终端侧可以做「读代码 → 改 → 跑命令」。适合查报错、补脚本、把手工操作沉淀下来，不适合拿着生产高权限乱跑。

## 权限比模型能力重要

生产凭证不要直接给无限权 Agent。先在开发机或只读账号上验证。删除、强推、毁资源类命令默认禁止；日志先脱敏再贴。这些听起来死板，事故半径小很多。

## 固定流程

一句话说清目标 → 写明可改目录和禁区 → 先只读调查 → 小步修改 → 跑测试或 curl → 人看 Diff 再提交。

提示可以长得朴素一点：

```text
目标：网关在上游 429 时把 Retry-After 透传回去
约束：只改 app/upstream.py 和 tests/；不升依赖；不改路由
验证：pytest -q；模拟上游 429 看响应头
先给调查结论，确认后再改代码。
```

## 几个实用场景

巡检脚本：GPU 是否可见、`/health`、磁盘、近几分钟错误数——生成后自己补超时和非零退出码。
日志归因：脱敏片段 + 配置，让它提假设和验证命令，别直接在生产执行修复。
批量对配置：对比各环境 `values.yaml` 的模型别名，产出草案，apply 仍人工。

CI 还是权威门禁。Agent 本地通过不等于可合并；lint/test 过了且人审过才行。

别指望它替代值班，也别一对话塞十个问题。拆开，才控制得住。
