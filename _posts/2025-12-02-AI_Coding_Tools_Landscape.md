## 先说结论

做运维和 Python 时，AI Coding 主要用来少写样板、快点翻陌生代码、把巡检和 Runbook 落成脚本。关键变更仍然要看完再合。

## 时间线记一下，免得神话新工具

- 2021–2022：Copilot 把补全变成日常
- 2023：对话写代码普及
- 2024：Cursor 这类 AI IDE 起来，多文件改动能用了
- 2025 年初：Claude Code 把 Agent 放进终端（Anthropic 大约 2 月前后推的）
- 之后一年：各家 Agent 都能改文件、跑命令，团队开始补规范，而不是只追更强模型

小版本跳得很快，选型看当下能力和代码能不能外发，别背参数表。

## 怎么选

写网关、改仓库、对着 Diff 细看——**Cursor** 更顺手，规则和项目上下文在那。
人在终端附近查日志、跑测试、做小修复——**Claude Code** 合适，但账号权限要收紧。
只是行级补全、不想被 Agent 带跑——**Copilot** 一类就够。
内网合规严——优先企业版或可私有化方案，别为了爽用个人版往外甩代码。

开源的 Continue、Aider 也能搭，整合成本自己掂量。

## 和前面笔记的关系

懂一点上下文窗口、工具调用，提示词会写得更准；部署和 ELK 那些仓库，正好拿来让 Agent 帮写压测、导出面板 JSON；Dify 插件骨架也能生成，但接口和权限得自己盯。

## 团队里的规矩

可以：生成样板、测试草稿、解读报错。
必须人审：鉴权、限流、灰度、生产配置、任何密钥相关。
不行：未审查就改生产、把密钥贴进对话、让 Agent 绕过评审。

提效来自少搬砖、快定位，不是无人值守改集群。后来在仓库里固定了一张「AI 可改 / 必须手改」清单，比空谈规范有用。
