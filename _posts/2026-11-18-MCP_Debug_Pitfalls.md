## 连不上

先在终端跑宿主配置里的同一条启动命令，看 stderr。常见是这三处：

- 命令不是绝对路径，宿主的 `PATH` 和终端不一样
- 依赖没装进该解释器，手动 `python` 能跑、宿主调用的却是另一个
- Windows 和 WSL 路径混用，盘符或 `/mnt` 对不上

配置里的 command 和手动成功的那条不一致，就是宿主没启动到那个环境。不要先改工具代码。

## 能连上，但从不调用

工具描述写得太糊，模型不知道何时该用。或者宿主还缓存着旧列表，改了名字也不刷新。重启 MCP 进程，必要时重开窗口，再看 `tools/list`。

写工具一直没动静，先看是不是停在「等待批准」。没有批准就不会执行，这不是模型没选中。

## 返回不对

一次塞进几万字日志，上下文被撑满，后面的回答会漂。按 `request_id` 截断，只回摘要和错误码。

异常被吞成 `{}` 时，模型会当成成功。失败要返回明确的 `error` 字段，不要空对象。

stdio 下不要 `print`。第三方进度条也关掉，日志走 stderr。stdout 上多一行普通文本，整段协议都会解析失败，表现仍像「连不上」。

## 顺序

1. 终端里原命令的 stderr
2. 宿主日志里的启动命令是不是同一条
3. `tools/list` 里有没有新工具
4. 一次最小只读调用的返回
5. 写工具是不是停在批准，而不是没被调用
