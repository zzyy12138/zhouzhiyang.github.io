## 这一年实际串起来的事

按时间看，大概是被问题推着走，而不是按课表推进：

- 3–5 月：ELK，先把日志和告警底盘搭上，后面排障都靠它  
- 6–7 月：Dify，从搭应用到生产部署，踩过直连模型和知识库乱调参  
- 8–9 月：补大模型与多模态基础，不然部署参数只能死记  
- 10 月：vLLM / SGLang / 量化，把「能推理」落到机器上  
- 11 月：观测、GPU、网关、灰度、成本，以及日志回灌 ELK  
- 12 月：Cursor / Claude Code 写运维脚本、Python 流式与重试、Dify Agent 对接自建推理、RAG 评测  

工作上对得上的几块：大模型运维、Python、AI Coding、Dify。每样都不算精通，但出事时大概知道该拆哪一层。

## 比较有底的、仍然发虚的

有底的：给推理定 SLO 和告警；处理常见 OOM/超时；网关鉴权限流；小流量灰度再回滚；Dify 接到自建模型；用 AI 写脚本但自己审 Diff。

仍发虚、工作里也确实磕过的：多集群调度和细粒度分账、评测自动化不够、Agent 工具权限与提示注入、数据合规默认方案。这些不是展望清单，是现阶段真实缺口。

## 留下来复用的三套手顺

**上线：** 评测 + 压测 + 看板 → 金丝雀放量 → 出问题先切路由回滚。  
**故障：** 告警 → 指标 → `request_id` 日志 → 对变更单 → 降流/切流 → 复盘进 Runbook。  
**AI 改代码：** 目标与禁区说清 → 只读调查 → 小步修改 → 测试 → 人审再合并。

年底回看，真正值钱的不是学过多少名词，而是这几套路子在线上用过、改过、还站得住。
